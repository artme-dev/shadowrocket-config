# Watcher и kill switch: доведение защиты Mac

5 ноября 2026. Пользователь попросил доделать внешнюю защиту после приёмки
основного Shadowrocket-профиля. Автоматическое обновление подписок по-прежнему
не включаем: это отдельная ранее отложенная задача.

## Фактическое исходное состояние

Watcher com.local.ai-watch не загружен. Однако два старых system LaunchDaemon
com.local.openai-killswitch и com.local.anthropic-killswitch **зарегистрированы**,
имеют StartInterval300 и недавно выполнялись (last exit0). Поэтому прежнее
общее утверждение «всё выключено» недостаточно точно. Факт загрузки PF-правил
нельзя установить без root; sudo -n сообщил, что требуется пароль.

В старых файлах: Claude ожидал прежний Xeovo; OpenAI regex указывал прежний
IPRoyal; документация и проверки ориентировались на старые выходы Blanc.
Исходники, установленные root-копии и состояние launchd — разные слои: правка
исходного файла не исправляет уже установленный LaunchDaemon сама по себе.

## Согласованное поведение

Пользователь явно выбрал закрытие Codex и ChatGPT при подтверждённом неверном IP.
Новая реализация требует два ответа одного реального хоста с одним неправильным
валидным IP; сетевые ошибки/таймауты и неожиданный HTML не дают основания закрывать
приложения. Для Claude сохраняется предупреждение без закрытия. Утечка на одном
реальном хосте не отменяется здоровым ответом другого.

## Подготовленная реализация

[mac-guards](../../../mac-guards/README.md) объединяет ожидания из текущих локальных
секретов, watcher, CLI gates, подготовку PF-таблиц, узкую root-установку и проверку.
Совместимые пользовательские wrappers в соседних каталогах направлены на новый код;
старые установленные root-задания до системного этапа не изменялись.

- Новый anchor249, известные AI-диапазоны и DNS-адреса, исключения DIRECT и внешних
  VPN/ISP-адресов. Никакой перезагрузки общего pf.conf или сброса всех states.
- Cached rules перед DoH при старте; неудачный DNS-refresh сохраняет cache.
- PF-reference удерживается один на boot. Старые задания250/251 отключаются и их
  правила снимаются только после успешного применения нового anchor.
- Watcher проверяет сервисные хосты через текущий default utun, а не IP-страницу
  другой группы. При отсутствии utun IP-пробы не отправляются напрямую.
- Состояния, логи, исходная резервная копия: ignored out/mac-guards/ и
  out/guards-2026-11-05/. Системная установка создаёт root-only backup.

## Выполненные проверки без привилегий

- Десять unit-тестов: подтверждение неверного IP, таймауты, отсутствие VPN,
  два реальных endpoint, безопасная имитация закрытия процессов, DIRECT/outer
  исключения, longest-prefix поведение таблиц, cache при отказе DNS, установка
  cached firewall до сетевого обновления.
- Python/shell/plist синтаксис и pfctl -n: успешно. Правила не применялись.
- Живой observe watcher через utun8: chatgpt.com, api.openai.com и api.anthropic.com
  подтвердили ожидаемый текущий IPRoyal. Приложения не закрывались.
- Подготовлены24DNS-host записи,450элементов OpenAI и5Claude в таблицах.

## Осталось для приёмки

Пользователь запускает mac-guards/enable.sh в Terminal без sudo перед командой;
скрипт сам запрашивает права для узкого системного этапа. Затем наблюдаем launchd,
healthy watcher и отчёт проверки прямых TCP с ростом block counters. До этого
защиту нельзя считать установленной и включённой. VPN выключать не требуется.
IPv6/UDP покрываются правилами, но отдельная живая проверка каждого протокола
не заявляется по одному TCP-тесту; существующие states намеренно не уничтожаются.
