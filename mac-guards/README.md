# Watcher и kill switch для финального artme.conf

Новая общая реализация заменяет старые `~/custom-network/ai-watch`,
`openai-killswitch` и `anthropic-killswitch`. Совместимые пользовательские входы
watch.sh, codex-guard и claude-guard направлены сюда. На 5 ноября подготовлено
и проверено без привилегий; включение firewall требует установки администратором.
Не считать наличие исходников доказательством, что защита включена.

## Разделение защиты

- **Shadowrocket:** AI-правила → свой ISP → группа входов. Нет альтернативного
  AI-выхода при отказе ISP. Это действует на совпавшие с правилами соединения.
- **Системный PF:** запрещает известные AI-IP вне utun. В таблицах — IP-правила
  принятого конфига (включая голос), актуальные адреса выбранных доменов. DIRECT
  IP-исключения и внешние адреса VPN/ISP вычтены. Общий /etc/pf.conf и другие
  anchors не перезагружаются, состояния всех соединений не сбрасываются.
- **Watcher:** раз в минуту проверяет реальные chatgpt.com, api.openai.com и
  api.anthropic.com. Запрос привязан к текущему default utun, env proxy обходится.
  Если default не utun, IP-запросы не выполняются. Это консервативная проверка для
  принятой конфигурации; произвольный split-tunnel VPN она не поддерживает.
- **CLI gate:** codex-guard/claude-guard разрешают запуск только после подтверждения
  ожидаемого IP на реальных хостах. Обычный codex-guard использует существующий alias.

Ожидаемый IP не зашит в код: prepare.py получает его из того же локального
`personal/secrets.local.json`, который используется сборщиком. Политика создаётся
в ignored `out/mac-guards/policy.json`; root получает отдельную защищённую копию.
Она предполагает, что IP SOCKS5-сервера совпадает с фактическим ISP-выходом — для
принятого IPRoyal это подтверждено. При другом провайдере сначала проверить факт.

## Поведение watcher, согласованное пользователем

При неправильном IP на OpenAI закрывает процессы `codex`, `Codex`, `ChatGPT`.
Достаточное подтверждение — два HTTPS-ответа одного реального хоста с одинаковым
валидным неправильным IP в одном цикле. Для здорового ответа повтор не нужен.
Ошибка curl, HTML challenge, отсутствие ip=, два разных IP и таймаут не считаются
подтверждённой утечкой. Они дают состояние недоступности/нестабильности и уведомление,
но приложения не закрываются. Если другой реальный хост подтвердил неправильный IP,
один здоровый ответ не отменяет тревогу. Claude — предупреждение, без закрытия.

Уведомления ограничены одним за 10 минут на сервис/состояние. Локальный журнал:
`~/Library/Logs/ai-watch.jsonl` (ротация около 2 MB); последнее состояние:
`~/Library/Caches/ai-watch/status.json`. В них есть IP, но нет паролей/ключей.
Изменение VPN, завершение приложений для симуляции и ослабление STUN не нужны.

## Установка и проверка

В обычном Terminal, от имени artem, **без sudo перед командой**:

```sh
/Users/artem/custom-network/shadowrocket-config/mac-guards/enable.sh
```

Скрипт:

1. Создаёт локальную политику и DNS seed через проверяемый HTTPS DoH; системный
   fake-IP DNS для PF не используется. Проверяет синтаксис PF без применения.
2. Требует здорового ответа на реальные сервисные пробы до включения закрытия.
3. Запрашивает sudo для узкой системной установки. Root-код/политика принадлежат
   root; периодическое задание не исполняет изменяемый пользователем код.
4. Сохраняет старые правила/состояние заданий в `/var/root/artme-ai-guard-backup-*`.
   Загружает новый `com.apple/249.ArtmeAIGuard`, затем снимает правила и отключает
   старые system jobs 250/251. Их файлы сохранены, но после reboot они не должны
   снова включиться. Если root com.apple/* отсутствует, установка прекращается.
5. Включает root LaunchDaemon `com.local.artme-ai-guard` (каждые 300 секунд)
   и пользовательский LaunchAgent `com.local.ai-watch` (каждые 60 секунд).
6. Проверяет здоровый ISP-выход и новые TCP-соединения, принудительно направленные
   через физический интерфейс. Для доказательства блокировки необходим рост
   счётчика соответствующего block-правила; одного timeout недостаточно.

Отчёты: `out/mac-guards/post-install-watch.json`, `pf-verification.json`,
`watcher-launchctl.txt`, `firewall-launchctl.txt`. Прямые тесты отправляют только
TCP SYN, без API-запросов, авторизации и пользовательских данных. VPN не выключается.
Проверка реального отключения/перезагрузки VPN сюда не входит: нужна отдельная
согласованная проверка, чтобы не оборвать рабочую связь.

Повторная проверка: `mac-guards/verify.sh` (PF-счётчики требуют sudo).
Без каких-либо принудительных закрытий: `/usr/bin/python3 mac-guards/guard.py watch`.

## Загрузка и обновление

При запуске root-задание сначала устанавливает сохранённый seed/cache, затем
пытается обновить DNS: отсутствие сети не должно открыть AI до окончания DoH.
Неудачное/частичное обновление сохраняет предыдущие адреса этого хоста. При
успешном ответе используется новый набор. Все действия сериализуются lock-файлом.
PF-reference token удерживается один на boot, а не добавляется каждые 5 минут.

Смена ISP, добавление доменов или обновление голосовых диапазонов требует заново
собрать полный конфиг и запустить enable.sh. Эта установка не включает автоматическую
сборку подписок, от которой пользователь ранее отказался. DNS IP уже перечисленных
хостов обновляются автоматически как часть работы kill switch.

## Аварийное выключение

```sh
/Users/artem/custom-network/shadowrocket-config/mac-guards/off.sh
```

Отключает только наши задания/правила; не выключает VPN и не включает старые задания.
Снимает только собственный PF reference, а не делает глобальный pfctl -d.
Для возврата исправленной защиты снова выполнить enable.sh. Не запускать старые
install/apply/off из исторических инструкций для независимых 250/251.

## Пределы защиты

- PF фильтрует адреса, а не приложения/домены. Новый неизвестный хост и иной IP,
  выданный браузерным DoH, могут не попасть в таблицу. Совместные CDN-IP способны
  блокировать чужой DIRECT-трафик. Явные IP-исключения DIRECT имеют приоритет;
  географическая база и DIRECT-домены Shadowrocket не воспроизводятся целиком в PF.
- Разрешаются utun0…utun255, а не только конкретный Shadowrocket. Фактический
  ISP-выход проверяет watcher; между проверками возможен неверный выход до минуты
  плюс время подтверждения. Это не мгновенная гарантия одного IP на уровне ОС.
- Уже существующие PF states намеренно не уничтожаются. Нативная проверка PF
  доказывает блокировку **новых** соединений, не отзыв любых ранее открытых.
- IPv4 direct TCP проверяется с ростом счётчика. Та же block-политика охватывает
  IPv6 и UDP, но отсутствие IPv6/недоступность контрольного UDP-сервера не выдаём
  за успешную отдельную сетевую проверку этих протоколов.
- Это защита Mac. LaunchAgent, root firewall и CLI alias на iPhone не переносятся.
  На iPhone остаётся защита совпавших AI-маршрутов внутри Shadowrocket.

## Разработка

`/usr/bin/python3 -m unittest discover -s mac-guards/tests -v` — изолированные
проверки подтверждения неверного IP, отсутствия закрытий при таймаутах/здоровом
выходе, исключений DIRECT/внешних узлов, сохранения DNS cache и порядка загрузки
firewall до DNS. Синтетический тест завершения подменяет pkill: приложения не трогает.
